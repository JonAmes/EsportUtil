# EsportsUtil - Data Contracts (Phase 1)

This document establishes the JSON structure contracts for the Client Agent and Server API, fulfilling the data contract requirements of Phase 1. All proprietary data captured by the `MachineState.ps1` engine (`machine_state`) must be passed verbatim and is considered an opaque JSON object, as per `docs/client-architecture.md`.

## 📦 1. Local Manifest (Client-to-Server)

This JSON payload is generated by the Client Agent and sent to the Server API upon connection, heartbeat, or state synchronization request.

```json
{
  "client_id": "unique_identifier_generated_at_onboarding",
  "device_pin": "immutable_hardware_identifier",
  "timestamp_utc": "YYYY-MM-DDTHH:mm:ssZ",
  "game_reports": [
    {
      "game_id": "unique_identifier_from_folder_scan",
      "installation_path": "absolute/path/to/game",
      "detected_version": "X.Y.Z",
      "is_current": true 
    }
  ],
  "machine_state": {
    // Opaque JSON payload generated verbatim by MachineState.ps1 engine.
    // Contains inventoried apps, display resolutions, startup items, etc.
    "cpu_count": 4,
    "os_version": "10.0",
    // ... hundreds of other engine-captured fields
  }
}
```

**Notes:**
*   `client_id` is transient and assigned during onboarding.
*   `device_pin` is the immutable hardware identity used for all lookups.
*   The `machine_state` object must be preserved exactly as outputted by the engine.

## 📜 2. Factory State Map (Server-Side Record)

This structure defines the baseline state used by the Server for comparison and remediation. These records are created when an operator designates a machine state as "golden."

```json
{
  "device_pin": "immutable_hardware_identifier",
  "server_record_id": "unique_server_reference_id",
  "golden_machine_model": "manufacturer_model_string",
  "baseline_version": "X.Y.Z",
  "manifest_snapshot": {
    // This holds the core, engine-output structure of the Local Manifest 
    // that served as the baseline for this golden record.
    "client_id": "...",
    "timestamp_utc": "...",
    "game_reports": [...],
    "machine_state": {
      // Verbatim engine JSON payload
    }
  }
}
```

**Notes:**
*   This structure is used by the Server to determine the correct baseline for a device matching the `DevicePin` or `golden_machine_model`.
*   The `manifest_snapshot` must retain the original, engine-generated format for consistency.
